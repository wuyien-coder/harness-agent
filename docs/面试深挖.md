# 面试深挖与回答边界

## 60 秒项目介绍

我的学位论文研究数学领域的知识检索与问答。我把其中的人物传记和关系图谱链路重构成前后端应用：用户可以上传文档、提问、查看引用，也可以查询人物关系。后端使用 FastAPI，文本通过稠密向量和 BM25 双路召回、加权融合（支持 RRF），关系问题结合图谱；LangGraph 负责节点编排。工程部分实现了 PostgreSQL/pgvector、Redis 缓存、Celery 摄取和数据库迁移，并保留了不依赖模型服务的本地演示。当前可展示本机演示和验证报告，容器的外部组件联调需要在有 Docker 的环境完成。

## 为什么要混合检索

传记里有专名、年代和学术术语。BM25 对词面匹配稳定，向量对语义相似表达有帮助；两者的优势依赖数据与模型，不能先假定融合一定更好。RRF 使用排名而不是原始分数，便于合并不同量纲的结果，但弱召回路仍可能拖累排序。可以通过单路、融合和精排消融逐项比较，讨论候选数、融合参数和实体过滤影响。

离线样例的 hash provider 只用来离线验证，不适合据此回答“语义召回提升多少”。真实质量要用 BGE 或指定 embedding、固定评测集重新测量。

## GraphRAG 在项目里做了什么

图谱保留人物、研究领域、籍贯和师承等关系。文本适合回答经历与贡献，结构化关系适合回答“师从谁”“有哪些人”以及人物之间的路径。Agent 根据问题选择文本、图谱或两者，把三元组与文本证据加入同一生成上下文。

当前实现是关系表和 NetworkX，不是 Neo4j。图谱规模、关系出处和别名匹配都会影响覆盖度；图谱里没有关系，不能直接解释成现实世界不存在这段关系。

## 为什么用 PostgreSQL 和 pgvector

关系数据、文档块、会话和向量放在同一数据库，便于统一连接、备份和迁移；pgvector 用向量距离操作符进行相似度排序。当前规模先保证数据一致和检索正确，再根据数据规模考虑 HNSW、过滤召回和索引调优。不要把“用了 pgvector”描述成“已经做过千万向量压测”。

向量维度与模型绑定，切模型不能只改一个名称后继续使用旧表和旧索引；要显式迁移/重建，并保留评测条件。

## 为什么需要 Celery 和 Redis

文件解析、分块、向量化和建索引可能耗时。API 创建任务并返回，worker 执行，用户在任务列表看到状态；数据库里的任务记录是业务事实，broker 只是消息通道。Redis 另外承担检索结果缓存，缓存键含索引版本与请求条件，避免文档更新后仍返回旧结果。

需要解释失败发生在“入队前”“worker处理中”还是“更新索引后”，并讨论幂等处理、重复消息、超时和失败恢复。当前演示 worker 并发 1；业务幂等不等于消息严格只投递一次，也没有宣称已完成分布式事务或高可用验证。

## SSE 是否真的流式

真实模型模式读取兼容接口的文本增量，按 SSE 事件发送给前端，代理关闭缓冲。检索结果先作为独立事件返回，用户能先查看证据。离线 stub 是抽取式结果分段展示，不能称作大模型 token 流。

流式请求失败时要展示错误，不能一直显示“生成中”；部分输出不代表完整答案已经保存。用浏览器或命令行查看事件到达时机，比只看最终页面文字更能证明实现。

## 如何证明引用可靠

引用包含块 ID、人物、章节、来源和摘录，可以回看检索证据；编号自检发现答案里超出上下文范围的引用。这个检查不证明每一句话都被证据支持，也不能消除幻觉。进一步可以做人工标注的段落相关性、答案忠实度评估和有/无证据拒答测试。

置信度是启发式检索信号，不是校准后的正确率。不同召回方式分数量纲不一致，需要以真实数据校准，不能把某个分数直接说成“有 90% 概率正确”。

## 你实际修过哪些问题

- 文档更新不能只比较块数，否则字数和块数不变时向量仍是旧内容；缓存也要跟随版本失效。
- 同一个人物多份资料的块 ID 必须包含文档身份，避免主键冲突或静默覆盖。
- 请求消融参数不能写进共享检索配置，否则并发请求会互相影响。
- 每轮用量必须单独统计，不能把累计 token 重复记入新一轮成本。
- 文件目录校验要判断真实父子路径，字符串前缀判断会误把同前缀的邻接目录当成允许目录。

面试前应在本版本代码和验证报告中逐项核对，具体修复状态以实际实现为准，不把审查发现当作已交付功能。

## 如何评价项目效果

先区分三类证据：自动化测试证明具体行为，消融报告比较检索策略，真实模型问答评估衡量答案质量。自动生成的评测集有弱标注和词面泄漏风险，人物级 gold 也不能证明段落正确。不要把离线测试通过、弱标注召回率和真实用户满意率混为一谈。

只有实际测量后才回答延迟、召回率、吞吐、成本等数字，并说明 provider、样本数、硬件与统计方法；本次新项目不继承旧目录的性能数字。

## 还欠缺什么

项目有共享 token 访问控制，没有完整账户体系和多租户权限；没有生产流量、容器联调结论或高可用承诺。可继续补充人工评测集、图谱来源、失败任务恢复、资源限制、身份隔离与容量测试。回答这些边界时结合实际需求解释优先级。
