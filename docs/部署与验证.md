# 部署与验证

## 本机完整模式

双击启动完整版.cmd，入口 http://127.0.0.1:8001/web/ 。脚本先启动项目独占 PostgreSQL / Redis，执行 Alembic，再启动 Celery worker 与 API，并实际检查三个组件。停止完整版.cmd 关闭新版；运行状态.cmd 检查进程。原项目 8000 端口独立保留。

完整配置在 .env，模型密钥在被忽略的 .runtime/private.env。不要将模型密钥填到页面的应用访问令牌输入框。更换模型或服务商时修改本机 .env，停止再启动；启动脚本保留已有配置。

PostgreSQL 16.15 + pgvector 0.8.6 与 Redis 7.2.8 已在本机实际启动。Windows PostgreSQL initdb 对中文路径存在编码限制，便携运行目录记录在 .runtime/state/portable-location.json。数据库端口 15432，Redis 16379，API 8001，均绑定 127.0.0.1，不注册系统服务。Redis 是社区 Windows 构建；Celery 本机使用 threads 池、并发 1，生产建议使用配置中的 Linux 容器。

日志为 .runtime/logs/api.log、worker.log、redis.log；数据库日志在便携运行目录 postgres.log。数据库数据与源码独立，停止服务不删除数据。

## 新环境 / Docker

依赖安装与完整模板见 README 和 .env.full.example。新环境需自行准备可用语料、模型缓存及密钥。容器使用 docker-compose.yml + docker-compose.full.yml，挂载 data/full、MODEL_CACHE_DIR 和 .runtime/private.env，安装 CPU ML 依赖。容器入口 8080，API 与 worker 共享同一镜像及数据。

本机没有 Docker，尚未实际构建运行容器；本机完整栈的通过不能写成容器验收通过。共享 Bearer token 仅提供应用访问控制，不是用户账户与多租户权限。CI 配置存在，但未推送执行的工作流不能宣称通过。

旧 reports/eval_current.json 为离线小样例回归；全量 BGE 的整体召回质量、人工答案质量、负载吞吐和生产稳定性需独立评测。
