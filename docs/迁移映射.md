# 从论文到简历项目的迁移映射

## 保留能形成区分度的部分

论文的价值在于数学人物领域数据、章节结构、稀疏与稠密检索对照、图谱关系增强和可复现评测。这些能力继续保留，新项目把它们组织为一个能交互演示的应用，而不是把领域资料换成泛化占位数据。

| 原论文/旧工程 | 新项目 | 面试可以解释什么 |
| --- | --- | --- |
| 命令行脚本调用链 | FastAPI 分层 API + React/TypeScript 界面 | 从研究原型到应用接口的边界设计 |
| SQLite/MySQL 关系数据 + Chroma 选项 | PostgreSQL 16 + pgvector，保留离线适配 | 数据与向量统一存储、余弦检索、迁移管理 |
| 同步/进程内摄取 | Celery + Redis，数据库任务状态 | 请求响应与耗时处理分离、失败可见性 |
| 进程内检索状态 | 版本化索引状态 + Redis 检索缓存 | 文档更新后跨进程刷新与缓存失效 |
| 单页 HTML 演示 | React + TypeScript + Vite | API 契约、引用面板、任务状态、流式交互 |
| 模型结果整体返回后切片 | 真实 provider 文本增量转发 + SSE | 首个事件时机、异常与断连处理 |
| 建表靠运行时 create_all | Alembic 版本迁移 | 可审查的数据库结构变更 |
| 可选 Agent 顺序执行 | LangGraph/顺序执行器共用节点 | 条件路由、图谱补召回、编排与业务解耦 |
| 稠密/BM25/RRF/图谱/精排 | 继续复用、修复一致性与请求隔离问题 | 为什么混合、何时需要精排、如何做消融 |
| 旧评测数字与报告 | 新版本重新运行并注明 provider | 不混用数据规模与测量条件 |

## 代码、配置、验证分开说

“实现了 pgvector 适配器”指存在真实连接和检索代码；“提供 Compose”指具备组件编排；“容器联调通过”必须有实际外部环境运行结果。当前环境没有 Docker，所以后者应等待真实验证。Redis/Celery 不能只在架构图中出现，必须分别从缓存调用和后台任务调用追到代码。

## 文件与数据处理

新项目位于独立文件夹，保留原论文与旧工程。迁移所需源码、全量语料及图谱；新版数据库和会话独立。按本机会话授权复用已有模型凭据，保存于 Git 忽略的私有配置；旧性能报告不作为新版结果。

全量语料已复制到本项目 data/full，亦可通过 `MATHKB_BIOGRAPHIES_DIR` 引用，图谱与评测数据通过 `MATHKB_DATA_DIR` 指定。不要把整套本机绝对路径写入公开仓库，也不要把全量语料与演示数据的指标混在同一张表中。
