# 多设备协同维护指南

目标：让这台机器与另一台设备能各自拉取代码、独立运行、改动可追溯，同时**不把密钥和大数据索引同步到仓库**。

## 一、资产分层原则

| 层级 | 内容 | Git 处理 |
|---|---|---|
| 代码与文档 | `harness/`、`src/`、`tests*/`、`scripts/`、`docs/`、`frontend/src/`、`*.md`、`pyproject.toml` | 纳入版本控制 |
| 配置模板 | `.env.example` / `.env.full.example` / `.env.production.example` | 纳入版本控制 |
| 真实密钥 | `.env` | **永不入库**，每台设备本地填写 |
| 索引与数据 | `.index/`（97MB）、`data/full/`、`.index/harness.db` 等 | **不入库**，新设备用脚本重建 + 从源数据生成 |
| 运行环境 | `.venv/`、`node_modules/`、`frontend/dist/`、`frontend/.npm-cache/` | 不入库，各自安装 |

`.gitignore` 已按上述规则配置好（含 `!.env.example` 等白名单）。

## 二、首次在新设备接入（从零开始）

仓库地址：`https://github.com/wuyien-coder/harness-agent.git`（私有库）

```bash
# 1. 克隆（私有库需 GitHub 账号授权；见第四节代理说明）
git clone https://github.com/wuyien-coder/harness-agent.git
cd harness-agent

# 2. 安装 Python 依赖（用各设备自己的 Python，不必是 D:/code/python.exe）
python -m venv .venv
source .venv/bin/activate          # Windows PowerShell: .venv\Scripts\Activate.ps1
pip install -r requirements.txt

# 3. 生成本地配置：从模板复制后填写自己的密钥
cp .env.example .env
# 编辑 .env：填 LLM API key、base_url 等；此文件已被 .gitignore 忽略

# 4. 重建 harness 专用索引库（脚本在副本内生成，不碰原项目数据）
PYTHONPATH=src:. python -m harness.seed_db

# 5. 恢复完整数据（二选一）
#    a. 有源语料：把 data/full/ 语料放到 data/full/，按原项目脚本重建 full 索引
#    b. 只跑 harness 演示：第 4 步已够，可跳过
```

## 三、日常维护规范

```bash
# 每次动手前先同步，避免分叉
git pull --rebase

# 改完提交：一条提交一个意图
git add <具体文件>
git commit -m "简短说明：改了什么、为什么"
git push
```

约定：

- **密钥变更只改模板**：要新增配置项时改 `*.example`，真实值只写本地 `.env`。
- **数据不进 Git**：`.index/`、`data/full/` 变更通过重建脚本或离线拷贝同步，不走提交。
- **冲突高发文件**：`HARNESS_README.md`、`harness/panel/index.html`。改动前先 `git pull --rebase`，冲突时用 `git status` 逐个解决，不要强推覆盖。
- **每次改完跑一次守护**：`PYTHONPATH=src:. python -m pytest tests_harness -q`（当前 71 项）。
- **回退能力**：提交粒度小，出问题可用 `git revert <commit>` 精确回退，不影响其他改动。

多人协作时加分支：`main` 为稳定版，功能改动开 `feature/xxx` 分支，改完在 GitHub 上提 PR 合并。

新设备克隆后若要推送，先确认该机的代理。若 `git push` 报 502，给 Git 单独设置代理（端口按该机代理软件为准）：

```bash
git config --global http.proxy http://127.0.0.1:7890
git config --global https.proxy http://127.0.0.1:7890
# 取消：git config --global --unset http.proxy
```

若没有可用代理，备选方案：

**方式 A：GitHub Desktop** — 登录 → Add local repository → 选项目目录 → Push，图形界面走自己的网络栈，通常能绕开 shell 的代理问题。

**方式 B：换国内平台** — Gitee / CNB 国内直连无需代理，换个 remote 地址即可。
